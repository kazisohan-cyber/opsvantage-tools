Event ID 4738: user account changed

What Event ID 4738 (user account changed) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Security · Severity: Low · MITRE ATT&CK T1098 · Updated 2026-11-08

Event ID 4738 is written whenever a user account is changed. Most of the time it is the helpdesk resetting a password or updating a phone number. But a handful of attribute changes are classic attacker moves, and 4738 lists exactly which attributes changed, so you can filter for them instead of reading every event.

The fields that matter

FieldWhat it tells you
Subject > Account NameWho made the change.
Target AccountThe account that was changed.
Changed AttributesOnly the attributes that changed have a value; the rest show -.
User Account ControlFlags switched on or off, such as 'Don't Require Preauth' - Enabled or 'Password Not Required' - Enabled.
SID History / Allowed To Delegate ToRarely changed in normal operations, and powerful when they are.

What is normal

Password resets (4738 alongside 4724), name and department updates from HR sync tools, and accounts being enabled or disabled by the helpdesk.

When Event ID 4738 is suspicious

  • Don't Require Preauth enabled: the account can now be AS-REP roasted (MITRE T1558.004).
  • Password Not Required or Don't Expire Password set on an admin or service account.
  • SID History added: the account may quietly gain the rights of another account, even a Domain Admin.
  • A delegation setting (Allowed To Delegate To) added to a user account.
  • Changes made by an account that is not part of IT, or outside working hours.

Common false positive: Identity sync tools and HR integrations can produce thousands of 4738 events a day. Filter on the User Account Control and SID History fields rather than alerting on every change.

Find Event ID 4738 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4738; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 4738
| project TimeGenerated, Computer, Account, Activity, EventData
| order by TimeGenerated desc

FAQ

What is AS-REP roasting?

If an account does not require Kerberos pre-authentication, anyone can ask the domain controller for data encrypted with that account's password and crack it offline. Look for 4768 events with pre-authentication type 0 for that account.

Does a password reset create Event ID 4738?

Usually yes, together with 4724 (password reset by someone else) or 4723 (user changed their own password).
