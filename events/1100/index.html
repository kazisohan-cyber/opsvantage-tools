Event ID 1100: event logging service shut down

What Event ID 1100 (event logging service shut down) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Security · Severity: Medium · MITRE ATT&CK T1562.002 · Updated 2026-11-03

Event ID 1100 means the Windows event logging service shut down. During a normal shutdown or reboot that is expected. When it happens and the machine keeps running, someone stopped logging, which is something attackers do before acting.

The fields that matter

FieldWhat it tells you
ProviderMicrosoft-Windows-Eventlog in the Security log.
TimeThe only real detail. Compare it with the System log.

What is normal

A 1100 just before a reboot, followed by event 6006 (event log stopped) and 6005 (event log started) in the System log.

When Event ID 1100 is suspicious

  • A 1100 without a reboot following it.
  • A gap in Security log events right after 1100.
  • A 1100 near a log clear (1102) or audit policy change (4719).

Common false positive: Planned reboots and patching windows.

Find Event ID 1100 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=1100; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 1100
| project TimeGenerated, Computer, Account, Activity, EventData
| order by TimeGenerated desc

FAQ

Can attackers stop logging without 1100?

Yes. Some tools suspend the event log service threads instead of stopping the service, which leaves no 1100. A sudden silence in the log is the sign to look for.
