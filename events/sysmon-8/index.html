Sysmon Event ID 8: createremotethread

What Sysmon Event ID 8 (createremotethread) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Microsoft-Windows-Sysmon/Operational · Severity: Medium · MITRE ATT&CK T1055 · Updated 2026-11-08

Sysmon Event ID 8 records CreateRemoteThread: one process starting a thread inside another process. That is the textbook way to inject code, so it is a strong signal when the source is something like PowerShell, an Office app or a binary from a temp folder, and the target is lsass.exe, explorer.exe or a svchost. Most Sysmon configurations exclude the handful of system and security processes that do this legitimately, which leaves a fairly quiet event.

The fields that matter

FieldWhat it tells you
SourceImageThe process that created the thread.
TargetImageThe process the thread was created in.
StartAddress / StartModuleWhere the new thread begins. An empty StartModule means the code is not backed by a file on disk: injected shellcode.
StartFunctionLoadLibraryA or LoadLibraryW is classic DLL injection.
SourceProcessGuid / TargetProcessGuidLink to Sysmon 1 events to see how each process was started.

What is normal

csrss.exe and wininit.exe creating threads in other processes, debuggers, and security products. A tuned Sysmon config usually filters these out.

When Sysmon Event ID 8 is suspicious

  • SourceImage is powershell.exe, rundll32.exe, regsvr32.exe, mshta.exe, an Office application or anything in a user-writable folder.
  • TargetImage is lsass.exe (credential theft), explorer.exe, svchost.exe or a browser.
  • StartModule empty, or StartFunction LoadLibraryA/LoadLibraryW from an unusual source.
  • Followed by network connections (Sysmon 3) from the target process to an address it never talked to before.

Common false positive: Accessibility tools, game anti-cheat, older antivirus and some monitoring agents inject legitimately. Exclude them by full path and signer, not by name.

Find Sysmon Event ID 8 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Sysmon/Operational'; Id=8; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

Event
| where TimeGenerated > ago(7d) and Source == "Microsoft-Windows-Sysmon" and EventID == 8
| project TimeGenerated, Computer, RenderedDescription, EventData
| order by TimeGenerated desc

FAQ

Does Sysmon log every kind of process injection?

No. Event 8 only covers CreateRemoteThread. Other techniques, such as APC injection or process hollowing, need Sysmon 10 (process access) or an EDR to see.

Why is StartModule empty?

The thread starts in memory that is not mapped to a file, which normally means injected code. Legitimate threads almost always start inside a DLL.

What should I do after a suspicious Sysmon Event ID 8?

Look at the source process's Sysmon 1 event (parent and command line), the target's network activity, and isolate the host if the target is lsass.exe.
