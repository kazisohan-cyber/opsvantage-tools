Event ID 4739: domain policy changed

What Event ID 4739 (domain policy changed) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Security · Severity: Medium · MITRE ATT&CK T1484 · Updated 2026-11-08

Event ID 4739 means a domain-wide policy was changed: the password policy, the account lockout policy or general domain settings such as the machine account quota. An attacker who lowers the lockout threshold to nothing or shortens the minimum password length makes the next password spray easier. Changes are rare, and every one should match a change ticket.

The fields that matter

FieldWhat it tells you
Change TypePassword Policy, Lockout Policy or Domain Policy (other domain settings).
Subject > Account NameWho made the change. Often a domain controller's computer account, because the DC applies the Default Domain Policy when Group Policy refreshes. When that happens, find the person who edited the policy in a 5136 on the GPO.
Changed AttributesEach setting with its new value, such as Lockout Threshold, Min. Password Length, Max. Password Age and Machine Account Quota. A - means unchanged.
DomainThe domain whose policy changed.

What is normal

Planned password or lockout policy changes made in the Default Domain Policy GPO, and the occasional burst when a new DC applies the policy for the first time.

When Event ID 4739 is suspicious

  • Lockout Threshold set to 0 (never lock out), or a much shorter Lockout Duration or Observation Window.
  • Min. Password Length or Password History Length lowered, or complexity turned off in Password Properties.
  • Machine Account Quota raised. Many hardened domains set it to 0 so normal users can't create computer accounts, which several privilege-escalation attacks rely on.
  • A change at an odd hour with no matching GPO edit by a known admin.

Common false positive: Security teams tightening the policy (longer minimum length, lower quota) also trigger 4739. Read the new values: hardening is good news.

Find Event ID 4739 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4739; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 4739
| project TimeGenerated, Computer, Account, Activity, EventData
| order by TimeGenerated desc

FAQ

Why does Event ID 4739 show a computer account as the Subject?

Password and lockout settings for the domain come from the Default Domain Policy GPO. When a domain controller applies it, the DC itself writes the change, so the Subject is the DC. The edit to the GPO itself is in Event ID 5136 with the real admin's name.

Which audit policy logs Event ID 4739?

Audit Authentication Policy Change, under Policy Change in Advanced Audit Policy, on domain controllers.

What should the Machine Account Quota be?

Default is 10, which lets any user add 10 computers to the domain. Unless you need self-service domain joins, 0 is safer, with joins done by a delegated account.
