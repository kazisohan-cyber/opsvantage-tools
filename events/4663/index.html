Event ID 4663: attempt to access an object

What Event ID 4663 (attempt to access an object) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Security · Severity: Informational · MITRE ATT&CK T1005 · Updated 2026-11-03

Event ID 4663 records that an account actually used access to a file, folder, registry key or other object that has auditing (a SACL) configured. It only appears where you turned on object access auditing, which is why it is quiet in most environments and very valuable where it exists: on file servers with sensitive shares it answers "who read or deleted this, and with which program".

The fields that matter

FieldWhat it tells you
Subject > Account NameWho accessed the object.
Object Type / Object NameFile, Key or other type, and its full path.
Accesses / Access MaskWhat was done: ReadData, WriteData, DELETE, WRITE_DAC and so on.
Process NameThe program used, such as explorer.exe, robocopy.exe or something unexpected.
Handle IDLinks to the matching 4656 (handle requested) and 4658 (handle closed).

What is normal

Users opening files on shares they work with, backup software reading everything once a night, and antivirus scanning.

When Event ID 4663 is suspicious

  • One account touching hundreds or thousands of files in minutes with WriteData or DELETE: ransomware encrypting a share.
  • Large volumes of ReadData from a sensitive folder by an account that rarely uses it: possible data theft.
  • Access through 7z.exe, rclone.exe, powershell.exe or archive tools on a finance or HR share.
  • DELETE on many files right after hours.

Common false positive: Backup agents, indexing services and antivirus generate huge volumes. Exclude their accounts and process names first.

Find Event ID 4663 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4663; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 4663
| project TimeGenerated, Computer, Account, Activity, EventData
| order by TimeGenerated desc

FAQ

Why don't I see any 4663 events?

Two things are needed: Audit File System (or Audit Registry) enabled in the audit policy, and a SACL on the folder or key that says which accesses to audit. Without the SACL nothing is logged.

What is the difference between 4656 and 4663?

4656 is logged when a handle is requested, whether or not it is used. 4663 is logged when the access is actually exercised, so it is the better record of what happened.
