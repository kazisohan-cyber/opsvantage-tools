Event ID 1102: security audit log cleared

What Event ID 1102 (security audit log cleared) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Security · Severity: Critical · MITRE ATT&CK T1070.001 · Updated 2026-11-03

Event ID 1102 means the Security log was cleared, and it records who did it. Logs don't normally get cleared: they roll over on their own. So a 1102 on a server almost always deserves a question, and attackers clear logs to hide what came before.

The fields that matter

FieldWhat it tells you
Subject > Account NameWho cleared the log.
Subject > Logon IDTies the action to the session (4624) that did it.

What is normal

An admin clearing a test machine, or troubleshooting with a documented change.

When Event ID 1102 is suspicious

  • Any 1102 on a domain controller or production server without a change record.
  • A clear soon after suspicious activity, such as new services, new accounts or unusual logons.
  • Clears by accounts that don't normally administer that host, or the System log cleared too (System Event ID 104).

Common false positive: Few. Some imaging or hardening scripts clear logs during build; those happen before a machine goes into service.

Find Event ID 1102 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=1102; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 1102
| project TimeGenerated, Computer, Account, Activity, EventData
| order by TimeGenerated desc

FAQ

How was the log cleared?

Usually with wevtutil cl Security, PowerShell Clear-EventLog or Event Viewer. 4688 or Sysmon 1 just before the 1102 often shows the command.

Can I still find what happened before the clear?

Check copies outside the machine: your SIEM, forwarded events, EDR telemetry and logs on other hosts the attacker touched.
