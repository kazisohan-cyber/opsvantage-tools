Event ID 4725: user account disabled

What Event ID 4725 (user account disabled) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Security · Severity: Low · MITRE ATT&CK T1531 · Updated 2026-11-03

Event ID 4725 records a user account being disabled. That is how leavers are handled, and also how an attacker can lock out administrators or security staff during an incident.

The fields that matter

FieldWhat it tells you
Target Account > Account NameWho was disabled.
Subject > Account NameWho disabled them.

What is normal

Leavers disabled by HR processes or identity tools.

When Event ID 4725 is suspicious

  • Admin or security team accounts disabled by an unexpected account.
  • Many accounts disabled at once outside an HR process.

Common false positive: Stale-account cleanup scripts disable inactive accounts in batches.

Find Event ID 4725 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4725; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 4725
| project TimeGenerated, Computer, Account, Activity, EventData
| order by TimeGenerated desc

FAQ

How is 4725 different from a lockout?

A lockout (4740) is automatic after bad passwords and clears itself. A disabled account stays disabled until someone enables it.
