Event ID 4723: password change attempt

What Event ID 4723 (password change attempt) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Security · Severity: Informational · MITRE ATT&CK T1098 · Updated 2026-11-03

Event ID 4723 records a user trying to change their own password. A reset by someone else is 4724 instead. Failures here are usually users missing the complexity rules.

The fields that matter

FieldWhat it tells you
Target AccountThe account whose password was changed.
SubjectWho made the change; the same account for a normal self-service change.
KeywordsAudit Success or Audit Failure.

What is normal

Users changing expiring passwords, often with a few failures first.

When Event ID 4723 is suspicious

  • A password change right after a suspicious sign-in for the same account.
  • Service accounts changing their own password unexpectedly.

Common false positive: Password expiry reminders cause bursts on the same day for many users.

Find Event ID 4723 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4723; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 4723
| project TimeGenerated, Computer, Account, Activity, EventData
| order by TimeGenerated desc

FAQ

Why did a 4723 fail?

Usually the new password broke the policy: too short, too recent, or the minimum password age had not passed.
