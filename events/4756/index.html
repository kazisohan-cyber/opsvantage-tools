Event ID 4756: member added to universal security group

What Event ID 4756 (member added to universal security group) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Security · Severity: Medium · MITRE ATT&CK T1098 · Updated 2026-11-08

Event ID 4756 means a member was added to a security-enabled universal group. Most universal groups are boring, but two of the most powerful groups in Active Directory are universal: Enterprise Admins and Schema Admins. Membership in either is effectively control of the whole forest, so a 4756 naming one of them deserves the same urgency as a new Domain Admin (4728). The event is written on the domain controller that processed the change.

The fields that matter

FieldWhat it tells you
Subject > Account NameWho made the change. Expect a small set of named admin accounts.
Member > Security ID / Account NameWho was added, shown as a SID and a distinguished name.
Group > Group NameThe universal group. Enterprise Admins and Schema Admins are the ones that matter most.
Group > Group DomainUsually the forest root domain for Enterprise Admins and Schema Admins.
Additional Information > PrivilegesNormally -.

What is normal

Changes to distribution-style security groups used for file or app access, done by identity staff or an identity management system such as MIM or an HR-driven provisioning tool. Additions to Enterprise Admins or Schema Admins should be rare enough that every one can be matched to a change ticket.

When Event ID 4756 is suspicious

  • Anyone added to Enterprise Admins or Schema Admins without a change ticket. Schema Admins in particular should be empty except during a planned schema update.
  • The actor is a service account, a helpdesk account or an account that has never managed groups before.
  • The new member is a recently created account (look for a 4720 shortly before) or a computer account.
  • An addition followed by a removal (4757) of the same member within hours: temporary rights used and cleaned up.

Common false positive: Schema updates for Exchange or a new domain controller version, where an admin is briefly added to Schema Admins. The change should be planned, and the member removed straight after.

Find Event ID 4756 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4756; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 4756
| project TimeGenerated, Computer, Account, Activity, EventData
| order by TimeGenerated desc

FAQ

What is the difference between Event ID 4728, 4732 and 4756?

They are the same action on different group scopes: 4728 for global groups (Domain Admins), 4732 for local and domain-local groups (Administrators, Remote Desktop Users) and 4756 for universal groups (Enterprise Admins, Schema Admins).

Which audit policy logs Event ID 4756?

Audit Security Group Management, under Account Management in Advanced Audit Policy, on domain controllers. Most baselines turn it on.

Should Schema Admins be empty?

Yes. Add an account only for the duration of a schema change and remove it afterwards. An alert on any 4756 for Schema Admins costs nothing in noise.
