Defender Event ID 1117: defender took action on malware

What Defender Event ID 1117 (defender took action on malware) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Microsoft-Windows-Windows Defender/Operational · Severity: Medium · Updated 2026-11-08

Microsoft Defender Event ID 1117 says Defender took action on a threat it detected: quarantined it, removed it or cleaned it. It follows the 1116 detection. A successful 1117 is good news for that file, but it is not the end of the investigation. Something put the file there, and if that something is still running, the same threat comes back.

The fields that matter

FieldWhat it tells you
Name / Severity / CategoryThe threat name (for example Trojan:Win32/Wacatac), its severity and its category.
PathWhere the file was. Downloads, Outlook temp folders and USB drives tell you how it arrived.
Process NameThe process that wrote or opened the file: a browser, outlook.exe, powershell.exe or something odd.
Detection UserThe user context at the time of detection.
ActionQuarantine, Remove, Clean or Allow.
Error Code / Error description0x00000000 means the action succeeded. Anything else means it may still be there.

What is normal

One 1116 and one 1117 for a file a user downloaded or received by email, quarantined successfully, with no repeats.

When Defender Event ID 1117 is suspicious

  • The same threat detected and removed again and again on one machine: something is re-dropping it, so look for persistence (scheduled tasks, services, Run keys).
  • Process Name is powershell.exe, wscript.exe, mshta.exe or rundll32.exe: it was written by a script or loader, not a user download.
  • Hacktool or credential-theft names (Mimikatz, Rubeus, Cobalt Strike beacons): a person is active on the machine.
  • A non-zero Error Code, or a later 1118 or 1119 (action failed).

Common false positive: Potentially unwanted apps and test files such as EICAR produce real 1117s. Check the threat category before escalating.

Find Defender Event ID 1117 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Windows Defender/Operational'; Id=1117; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

Event
| where TimeGenerated > ago(7d) and EventLog == "Microsoft-Windows-Windows Defender/Operational" and EventID == 1117
| project TimeGenerated, Computer, RenderedDescription, EventData
| order by TimeGenerated desc

FAQ

Is the threat gone after Event ID 1117?

That file is gone if the Error Code is 0. Check where it came from (Path and Process Name) and whether the same detection repeats.

What are Event IDs 1118 and 1119?

Defender tried to act and failed: 1118 for a non-critical failure, 1119 for a critical one. Both mean the threat may still be active.

Where do Defender events live?

In Applications and Services Logs > Microsoft > Windows > Windows Defender > Operational.
