Sysmon Event ID 7: image loaded

What Sysmon Event ID 7 (image loaded) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Microsoft-Windows-Sysmon/Operational · Severity: Informational · MITRE ATT&CK T1574.002 · Updated 2026-11-08

Sysmon Event ID 7 records a DLL (image) being loaded into a process. Logging every load would bury you, so most configurations log only selected DLLs or unsigned ones. Tuned that way, it catches DLL side-loading (a signed program in a user folder loading a malicious DLL next to it) and in-memory tradecraft such as .NET assemblies or PowerShell running inside processes that should never host them.

The fields that matter

FieldWhat it tells you
ImageThe process that loaded the DLL.
ImageLoadedFull path of the DLL.
Signed / Signature / SignatureStatusWhether the DLL is signed, by whom, and whether the signature is valid.
HashesHashes of the DLL, for threat intel lookups.
OriginalFileNameThe name compiled into the file, which survives renaming.

What is normal

Signed Microsoft and vendor DLLs loaded from System32, Program Files and the application's own install folder.

When Sysmon Event ID 7 is suspicious

  • A signed executable running from AppData, Temp, ProgramData or C:\Users\Public loading an unsigned DLL from the same folder: classic side-loading.
  • clr.dll or clrjit.dll loaded into a process that is not a .NET app, such as notepad.exe or rundll32.exe: in-memory .NET assembly execution.
  • System.Management.Automation.dll loaded by something other than PowerShell: PowerShell running without powershell.exe.
  • dbghelp.dll or dbgcore.dll loaded by an unusual process right before lsass access (Sysmon 10): a memory dump.

Common false positive: Developer tools and software that ships unsigned plug-ins. Baseline by Image path and signer rather than by DLL name alone.

Find Sysmon Event ID 7 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Sysmon/Operational'; Id=7; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

Event
| where TimeGenerated > ago(7d) and Source == "Microsoft-Windows-Sysmon" and EventID == 7
| project TimeGenerated, Computer, RenderedDescription, EventData
| order by TimeGenerated desc

FAQ

Why don't I see Sysmon Event ID 7?

Most Sysmon configurations leave image load logging off or tightly filtered because of volume. Enable it for specific DLLs or for unsigned images only.

What is DLL side-loading?

An attacker drops a legitimate, signed program together with a malicious DLL that the program loads by name. The process looks trusted, but the code running inside it is not.

Is an unsigned DLL always bad?

No. Plenty of legitimate software ships unsigned DLLs. The location (user-writable folders) and the process loading it are what make it suspicious.
