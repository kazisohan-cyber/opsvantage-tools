Event ID 4670: permissions on an object changed

What Event ID 4670 (permissions on an object changed) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Security · Severity: Low · MITRE ATT&CK T1222.001 · Updated 2026-11-03

Event ID 4670 is logged when the permissions (the security descriptor) on an audited object change: a file, folder, registry key or service. Attackers change permissions to give themselves access, and ransomware sometimes takes ownership and resets ACLs before encrypting. The event shows the old and new permissions side by side in SDDL.

The fields that matter

FieldWhat it tells you
Subject > Account NameWho changed the permissions.
Object Type / Object NameWhat was changed.
Process NameThe tool, for example icacls.exe, takeown.exe, explorer.exe or powershell.exe.
Original Security DescriptorThe permissions before, in SDDL.
New Security DescriptorThe permissions after. Look for new (A;;FA;;;WD) (full access for Everyone) or (A;;FA;;;BU) (Users) entries.

What is normal

Administrators adjusting share or folder permissions, installers setting permissions on their own folders.

When Event ID 4670 is suspicious

  • Everyone or Authenticated Users given full control on a sensitive folder.
  • Many 4670 events from icacls.exe or takeown.exe across a file server in a short time.
  • Permission changes on service registry keys or binaries, which can let a normal user replace a service.

Common false positive: Software updates and installers reset permissions on their own folders. Filter by known installer processes and system accounts.

Find Event ID 4670 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4670; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 4670
| project TimeGenerated, Computer, Account, Activity, EventData
| order by TimeGenerated desc

FAQ

How do I read the SDDL in 4670?

Each (A;...;...;...;SID) block is an allow entry: the rights code (FA full access, FR read, FW write) and who it applies to (WD Everyone, BU Users, BA Administrators, or a full SID). Compare the old and new strings for added entries.
