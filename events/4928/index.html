Event ID 4928: ad replica source naming context established

What Event ID 4928 (ad replica source naming context established) means, the fields to check, what is normal and what is suspicious, with PowerShell and KQL queries to find it.

Log: Security · Severity: Low · MITRE ATT&CK T1207 · Updated 2026-11-08

Event ID 4928 is written on a domain controller when it sets up replication of a naming context (a directory partition) from another DC. On a stable domain you see it when a DC is added, promoted or rebooted, and rarely otherwise. That rarity is what makes it useful: the DCShadow attack registers a machine as a temporary domain controller, and the moment it starts pushing changes, 4928 records a replication source that is not one of your DCs.

The fields that matter

FieldWhat it tells you
Destination DRAThe DC that recorded the event and now replicates from the source.
Source DRAThe replication partner, shown as its NTDS Settings object. This is the field to check.
Source AddressThe partner's DNS name or GUID-based address.
Naming ContextThe partition being replicated, for example DC=corp,DC=local, CN=Configuration,... or CN=Schema,....
Status Code0 when the connection was set up successfully.

What is normal

A burst of 4928 events on every DC after a new domain controller is promoted, during a site topology change, or after a DC restore. The Source DRA is always a server in the Domain Controllers OU.

When Event ID 4928 is suspicious

  • A Source DRA or Source Address that is a workstation or any machine not listed as a domain controller: classic DCShadow.
  • A 4928 followed within minutes by a 4929 removing the same source, outside any planned DC work.
  • Replication of the Schema or Configuration partition from an unexpected source.

Common false positive: New or rebuilt domain controllers. Keep a current list of DC names and compare against it rather than alerting on every 4928.

Find Event ID 4928 with PowerShell

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4928; StartTime=(Get-Date).AddDays(-7)} -MaxEvents 50 |
  ForEach-Object {
    $d = [ordered]@{ Time = $_.TimeCreated; Computer = $_.MachineName }
    ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name] = $_.'#text' }
    [pscustomobject]$d
  } | Format-List

Microsoft Sentinel (KQL)

SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 4928
| project TimeGenerated, Computer, Account, Activity, EventData
| order by TimeGenerated desc

FAQ

Which audit policy logs Event ID 4928?

Audit Detailed Directory Service Replication, under Advanced Audit Policy > DS Access, on domain controllers. It is off by default.

What is DCShadow?

A technique (Mimikatz lsadump::dcshadow) that temporarily registers a machine as a domain controller so it can push changes, such as SID History or group membership, through replication without the normal change events. 4928 and 4929 are among the few traces it leaves.
