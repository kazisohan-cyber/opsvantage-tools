Windows logon types explained

Every logon type in Event ID 4624 and 4625, from 2 to 13, with what it looks like in normal use and which ones point to RDP abuse, lateral movement or pass-the-hash.

Updated 2026-11-03 · 8 min read

Filter a domain controller's Security log to Event ID 4624 for one day and you'll get tens of thousands of successful logons. Almost all of them are boring. The Windows logon type, a single number in each event, is the quickest way to find the few that aren't: the RDP session from an IP nobody recognises, the admin account suddenly authenticating to twenty workstations, the type 9 logon that shouldn't exist at all.

Every successful logon writes 4624 and every failure writes 4625; both carry the same logon type field. This is what each value means and which ones deserve your attention.

The four that matter most in investigations

Type 10: Remote Desktop

Every RDP session should be explainable. A type 10 logon whose Source Network Address is a public IP means RDP is reachable from the internet, which is one of the most common ransomware entry points. Check the preceding 4625 failures: a burst of failures and then a type 10 success is a guessed password.

Type 3: Network

Type 3 is the noisiest type and the one attackers hide in. Normal type 3 traffic goes from workstations to servers. Watch for workstation to workstation logons, admin accounts logging on to many machines in a short time, and NTLM where Kerberos is expected. Tools such as PsExec, WMI and SMB-based lateral movement show up here, usually next to a 7045 (new service) or 5145 access to ADMIN$.

Type 9: NewCredentials

Legitimate type 9 logons come from runas /netonly, which few people use. Type 9 with logon process seclogo and authentication package Negotiate on a workstation is a strong indicator of pass-the-hash. It deserves an alert on its own.

Type 2: Interactive with privileged accounts

Domain Admins should not log on interactively to ordinary workstations. Doing so leaves their credentials in memory where tools can dump them. Interactive logons by privileged accounts outside admin workstations are a hygiene finding even when nothing malicious happened.

Where I'd spend alert budget: type 10 from public IPs, type 9 with seclogo, and privileged accounts with type 2 or 10 on non-admin machines. Those three are rare in healthy networks and almost always worth a look. Alerting on raw type 3 volume, by contrast, mostly produces noise; baseline it per account instead.

Other fields to read with the logon type

  • Elevated Token (Yes/No): whether the session has admin rights.
  • Logon ID: links this logon to everything the session did afterwards (process creation 4688, logoff 4634).
  • Logon Process / Authentication Package: User32/Negotiate for normal interactive, NtLmSsp/NTLM for NTLM network logons.
  • Special privileges (4672): logged right after 4624 when the account has admin-level privileges.

Quick hunting queries

// Sentinel: RDP logons from public IPs in the last 7 days
SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 4624 and LogonType == 10
| where not(ipv4_is_private(IpAddress)) and IpAddress !in ("-", "127.0.0.1")
| summarize Logons = count(), Hosts = make_set(Computer) by TargetAccount, IpAddress
// Sentinel: possible pass-the-hash (type 9 via seclogo)
SecurityEvent
| where TimeGenerated > ago(7d) and EventID == 4624 and LogonType == 9
| where LogonProcessName has "seclogo"
| project TimeGenerated, Computer, TargetAccount, SubjectAccount, IpAddress

FAQ

What's the difference between logon type 3 and logon type 10?

Type 3 is network access to a resource, such as opening a share, without an interactive desktop. Type 10 is a full Remote Desktop session. With Network Level Authentication on, an RDP connection first authenticates as type 3, and the desktop session that follows is logged as type 10.

Is logon type 9 always malicious?

No. runas /netonly creates type 9 logons, and a few admin tools use it. It's just rare enough in most environments that each one is worth checking, especially with the seclogo logon process on a workstation.

Why does the same user have hundreds of type 3 logons a day?

Group Policy processing, mapped drives, printers and many management agents authenticate over the network repeatedly. That volume is normal. What matters is where those logons come from and go to.

Which logon type do cached credentials use?

Type 11 for interactive logons with cached credentials (a laptop off the corporate network), and 12 or 13 for cached remote interactive and unlock logons.
